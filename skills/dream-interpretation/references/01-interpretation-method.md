# 解梦方法

## 先确定用户要什么

用户可能在问不同问题：查一个符号的传统说法、解释一段完整梦境、理解反复梦、缓解噩梦带来的不安，或反向查询哪些梦象对应某类传统梦兆。先直接处理当前问题；只有缺项会改变答案时才追问。

## 场景结构

把完整梦境还原为一条事件链，而不是一袋互不相干的符号：

```text
起始处境 → 关键对象出现 → 梦者/他人采取动作 → 状态发生变化 → 梦中结果 → 醒后情绪
```

匹配条目时至少区分：

| 维度 | 容易改变匹配的差别 |
|---|---|
| 主体 | 梦者、伴侣、亲属、陌生人、死者 |
| 动作 | 看见、得到、丢失、追赶、被咬、杀伤、乘坐、进入、离开 |
| 状态 | 清/浑、明/暗、活/死、完整/破损、满/空、干/湿 |
| 方向 | 入宅/出门、上升/坠落、靠近/远去、得到/交给别人 |
| 结果 | 脱险、受困、寻回、分离、团聚、醒前未完成 |

原文中“蛇”不是一个固定判断：蛇入门、蛇咬人、蛇随人去、蛇绕身各是不同条目。其他对象同理。

## 传统条目的匹配等级

### 精确匹配

核心对象、关键动作和决定性状态一致。允许古今用词不同，例如“牙齿脱落”对应“齿自落”，但要保留实际差异，不增加原文没有的时间、人物身份或结果。

### 近似匹配

至少对象和关键动作一致，但缺少或冲突一个限定条件。回答时并列写出：原梦是什么、原条目是什么、缺少哪项。例如用户只说“梦见井水”，不能在清浑未知时直接选择“取井水清吉浑凶”的任一半。

### 类比

只有上位类别或功能相近，例如现代交通工具与古代车船。类比只能作为解释线索，不能写成原典明载。手机、互联网、办公软件等现代物件没有直接古籍条目时，应承认没有精确对应。

### 不匹配

只有一个常见字重合，或命中的是条目的梦兆结果而非梦中场景，不算证据。不要为了给答案而强行牵合。

## 多条目合并

1. 先选主事件，即没有它梦的结果就不会发生的动作。
2. 用对象状态和方向筛掉不合条目。
3. 其余符号只解释它们如何加强、限制或转折主事件。
4. 两条精确规则冲突时保留冲突，检查是否其实对应梦的不同阶段；仍无法裁决就降低结论强度。
5. 不计算吉凶票数，不把多个含义机械相加，也不因结尾是吉词就抹掉梦里的强烈恐惧。

## 语境解释

语境解释不是另一套预言。按下列优先级寻找现实含义：

1. 用户对该人物或物件的个人联想；
2. 梦中的情绪与行动模式；
3. 近期真实经历、期待、冲突、媒体刺激和睡眠状态；
4. 较宽泛的象征类比。

不要宣称每个符号都有跨文化、跨个人的固定心理含义，也不要把一次梦境诊断为创伤、焦虑症或其他疾病。用户没有提供现实背景时，使用条件句，例如“如果你近期正在等待消息，这一段更可能是在加工等待感”，不要替用户编经历。

## 反向查询

用户问“什么梦代表发财/远客/迁居”等传统问题时，可以直接在辞典全文检索结果词。但输出必须说明这是反向查到的民俗条目清单，不表示做了这些梦就一定发生对应事件；优先列三至五个清楚、无残缺的条目。

## 回答质量检查

- 是否明确了精确、近似、类比或无匹配？
- 是否把条目中的结果误写成现实事实？
- 是否遗漏了会造成相反匹配的状态或方向？
- 是否沿一条主事件链解释，而不是逐个名词讲故事？
- 是否加入了原文没有的应期、人物身份或因果？
- 是否对残缺原句保持了不确定性？
